# 公司研究系统设计

这份设计补上现有投研流程里的三段空白：数字没有来源账、每家公司都走同一套分析模板、报告结论多为复述。它不替换已经在跑的财务、竞争、估值、信号整合和监测，而是规定这些模块何时开工、引用什么、怎样才算产生洞察。

## 系统要解决的问题

投资研究不是「财报进去，建议出来」。同一条毛利率下降，在不同公司里权重完全不同：可能是定价权，可能是产品结构，可能是成本时滞。权重取决于这家公司的历史、竞争格局和管理层行为，不能在流程开始前写死。

因此系统分成三件能自动做完的事，和一件留给人的事。

| 层 | 做什么 | 不做什么 |
|----|--------|----------|
| 事实底账 | 按来源等级采集、对账、留缺口 | 不解释原因，不填预测 |
| 角度挖掘 | 从异常里找出 3–5 个会改逻辑的问题 | 不把固定大纲当成角度 |
| 专项分析 | 只回答入选角度 | 不平均用力写满模板 |
| 洞察 | 机制、双证据、证伪条件 | 不给买卖评级 |
| 人 | 采信哪条、访调什么、下多大仓位 | — |

买卖评级仍由最终报告给出，但评级理由必须引用洞察 ID。没有洞察支撑的形容词不能单独成为结论。

## 流程

```
公司名
  │
  ▼
source-curator ──► 事实底账
  │                 只有 S0/S1 能进入事实表
  ▼
angle-miner ──► 分析角度
  │              没有 M≥3 的角度则停止
  ▼
任务单上的专项代理（财务 / 竞争 / 估值 / 宏观）
  │              每个代理只回答分给它的问题
  ▼
signal-integrator ──► 矛盾仲裁
  ▼
insight-engine ──► 洞察卡片
  ▼
quality-checker ──► 四道门复核
  ▼
research-report-summarizer ──► 报告第一节是洞察
  ▼
研究员：采信、访调、写入假设库、交给监测
```

入口命令是 `/company-research [公司名]`。原有 `/analyze-company` 保持不变，适合已经知道要看哪几张表、只要快速出完整报告的情况。

## 准确的数据从哪里来

来源规则写在 `.claude/knowledge/data-sources.md`，由 `source-curator` 执行。

等级从高到低：

- **S0** 公司法定披露。A 股用巨潮资讯，港股用 HKEXnews，美股用 SEC EDGAR。
- **S1** 统计局、海关、央行、主管部门和交易所的原文。
- **S2** 同花顺、东方财富的行情与一致预期。财务数字必须回对 S0。
- **S3** 券商研报和媒体。只能产生待验证假设。
- **S4** 招聘、招投标、渠道。只能提示下一步去核实什么。

对账有六条硬规则：同指标取最高等级；同级冲突两列都留，不取平均；S2 与 S0 金额差超过 1% 或比率差超过 0.5 个百分点时采用 S0 并记录差额；口径写进事实陈述；缺失保持缺失；卖方预测单独进预期表。

每条事实有稳定 ID，例如 `F-revenue-FY2025`。洞察只能引用这些 ID。这是防止「分析过程中长出新数字」的办法。

## 模型

角度挖掘和洞察只由 Claude Opus 完成。这两个角色的定义里写了 `model: opus`。在 Cursor 里它们作为子任务启动，模型用 `claude-opus-5-5-high`。事实底账、专项分析和质量检查不占用这一要求。主会话模型不得代写角度文件或洞察文件；质量检查退回的洞察仍交回 Claude Opus 修改。

## 分析角度怎么挖

`angle-miner` 不从行业清单里选题。它做三步。

1. 用底账把利润拆成 2–4 个真正在动的变量。拆不开，就把「缺分部披露」本身当成角度。
2. 扫四类异常：相对自身历史、相对同业、利润与现金背离、公告表述与资本开支或分红不一致。
3. 每个异常写成一个问题，并给出 2–3 条互相排斥的机制。两条会被同一份数据同时证实的解释，合并成一条。

打分：

| 分项 | 问题 |
|------|------|
| 重要性 M | 结论反转后，买卖方向或目标价会不会变 |
| 未解度 U | 现有事实能不能分开这些机制 |
| 可判别 D | 下一份报告或一个访调问题能不能分开 |
| 时效 T | 本季就会变，还是三年不动 |

入选分 = M × (U + D)。时效只排序，不淘汰。M 低于 3 的角度直接丢掉。保留 3 到 5 个；一个都不够格时，输出「当前没有值得深挖的角度」并停止，不用模板把报告凑满。

入选角度变成任务单。财务代理只看科目和现金流，竞争代理只看份额和定价，估值代理只改那些被角度点名的假设。宏观只在任务单出现周期或政策时才启动。

## 怎样才算洞察

`insight-engine` 用四道门过滤候选句子。

1. **非复述**：删掉这句话，研究员的假设会变。
2. **有机制**：写清事实怎样传到利润或估值。
3. **双证据**：至少两个事实 ID，且不能都来自同一份研报。
4. **可证伪**：写明未来哪个观测会推翻它。

不过门的句子降为观察，留在洞察文件里，避免报告把它们写回核心结论。

置信度看证据等级和竞争机制是否还在，不看措辞强弱。低置信度可以保留，但不能单独支撑评级。

洞察卡片固定八项：主张、被改写的假设、机制、证据 ID、反证、证伪条件、监测阈值、置信度。监测阈值之后交给现有的假设库和 `/monitor`，不在这里再造一套告警。

估值假设若与某条洞察冲突，只写修正建议（原假设、改成什么、依据哪条洞察），不在这一层重算目标价，也不写推荐等级。

以下内容明确留给人，不包装成洞察：管理层意图、没有历史先例的政策或黑天鹅、仓位与赔率。

## 和现有模块的关系

| 已有模块 | 在本流程中的位置 |
|----------|------------------|
| financial-data-fetcher | 仍可供单独取数。洞察流程改由 source-curator 出底账，避免两套口径 |
| financial-analyst、competitor-analyst、valuation-expert | 按任务单被调用，不再默认三份并行写满 |
| macro-researcher | 仅当角度含周期或政策 |
| signal-integrator | 洞察之前的矛盾仲裁，原有七类矛盾规则继续用 |
| quality-checker | 增加洞察审计：事实 ID、等级、证伪条件、有没有把推断写成事实 |
| research-report-summarizer | 报告第一节改为洞察，评级理由挂洞察 ID |
| 假设库、monitor、dashboard、案例库 | 流程结束后的沉淀。角度挖掘会读同行业已结束案例，避免重复旧盲区 |

## 一次研究的完成定义

同时满足下面四条，才算这次公司研究做完：

- 事实表里没有无来源、无口径、或由预测填上的数字。
- 角度文件有入选、有淘汰理由；或者明确写了没有值得深挖的角度并已停止。
- 每条洞察都过了四道门，观察没有被删掉。
- 报告里的评级理由能点回洞察 ID；点不回的判断标成研究员个人判断。
